# 우리 서버 정상영업 하나요

동국대학교 펍서버와 이클래스의 외부 접속 상태를 확인하는 작은 상태 페이지입니다.
1분마다 접속을 확인하고, 최근 7일의 기록을 그래프로 보여줍니다.

**[상태 페이지 보기 →](https://ping.butterflyjin.kr/)**

## 주요 기능

- **서비스별 현재 상태** — 펍서버 포트 101·102의 TCP 연결과 이클래스의 HTTPS 응답을 확인합니다.
- **기간별 그래프** — 최근 1시간, 24시간, 7일의 접속 기록을 살펴볼 수 있습니다.
- **이상 구간 툴팁** — 막대에 마우스를 올리면 성공률과 연속 실패가 관측된 시간을 바로 표시합니다. 키보드 방향키로도 이동할 수 있습니다.
- **장애·복구 이력** — 연속 3회 실패하면 장애로 기록하고, 다음 정상 응답에서 복구 처리합니다.
- **가벼운 실행 환경** — Python 표준 라이브러리, SQLite, HTML/CSS/JavaScript로 구성했습니다.

### 그래프 읽는 법

| 조회 기간 | 막대 한 칸 | 막대 수 |
| --- | --- | --- |
| 1시간 | 1분 | 60개 |
| 24시간 | 1시간 | 24개 |
| 7일 | 4시간 | 42개 |

초록색은 모두 성공, 노란색은 성공과 실패가 섞인 구간, 빨간색은 모두 실패한 구간입니다. 기록이 없거나 관측 공백이 있는 구간은 회색으로 표시합니다.

툴팁 예시:

```text
11. 17. 01:50 ~ 11. 17. 05:50
99.17% 성공
11. 17. 04:26 ~ 04:28 동안 접속 이상 확인
```

성공률은 **실행한 검사 중 성공한 비율**입니다. 이상 구간은 첫 실패부터 다음 정상 확인까지의 관측 범위이며, 실제 장애 시작·종료 시각과는 차이가 있을 수 있습니다.

## 로컬 실행

**Python 3.9 이상**이 필요합니다. 운영 환경에서는 Ubuntu의 Python 3.12로 검증했습니다.

저장소 디렉터리에서 실행합니다.

```sh
python3 server.py
```

브라우저에서 **http://127.0.0.1:9085** 를 엽니다. Python 패키지를 추가로 설치할 필요는 없습니다.

| 환경 변수 | 기본값 | 용도 |
| --- | --- | --- |
| `PORT` | `9085` | 로컬 HTTP 서버 포트 |
| `STATUS_DB` | `server.py` 옆의 `status.db` | 검사 기록을 저장할 SQLite 파일 |

다른 서비스를 확인하려면 실행 전에 `server.py`의 `TARGETS`와 `raw_probe()`에 정의된 이름·주소·포트를 수정하세요. 기본 대상은 동국대학교 서비스이며, SSH 로그인이나 이클래스 인증은 수행하지 않습니다.

## Ubuntu 서버에 배포

소스를 서버에 복사한 뒤 저장소 디렉터리에서 실행합니다.

```sh
sudo sh deploy.sh
```

설치 스크립트는 전용 계정을 만들고 systemd 서비스로 등록합니다.

| 항목 | 경로·이름 |
| --- | --- |
| 서비스 | `dongguk-status` |
| 실행 계정 | `dongguk-status` |
| 코드 | `/opt/dongguk-status` |
| 데이터베이스 | `/var/lib/dongguk-status/status.db` |

공개 접속에는 HTTPS 역방향 프록시가 필요합니다. Caddy를 별도로 설치하고, [`deploy/Caddyfile.example`](deploy/Caddyfile.example)의 도메인을 본인 도메인으로 변경해 사용하세요. 기존 Caddy 사이트가 있다면 설정을 병합합니다. DNS와 방화벽의 웹 포트 허용도 별도로 설정해야 합니다.

상태와 로그 확인:

```sh
systemctl status dongguk-status --no-pager
sudo journalctl -u dongguk-status -n 30 --no-pager
curl -fsS http://127.0.0.1:9085/api/status
```

## 테스트

서버 테스트:

```sh
python3 -m unittest discover -s tests -v
```

브라우저 테스트:

```sh
npm ci
npx playwright-core install chromium
npm run test:browser
```

브라우저 테스트는 모의 데이터를 사용합니다. 모바일·데스크톱 화면, 그래프 칸 수, 툴팁, 자동 갱신과 화면 흔들림을 확인합니다. 이미 설치된 Chrome을 사용하려면 `CHROME_PATH`에 실행 파일 경로를 지정하세요.

## MCP로 조회

MCP 클라이언트에서 기존 기록을 읽을 수도 있습니다. 이 도구를 호출해도 학교 서버를 추가 검사하지 않습니다.

| 도구 | 용도 |
| --- | --- |
| `get_status` | 서비스별 마지막 관측 상태·응답 시간 |
| `get_history` | 1시간·24시간·7일 그래프와 이상 구간 |
| `get_incidents` | 확정된 장애·복구 이력 |

선택 기능이며 Python 3.10 이상과 별도 MCP SDK가 필요합니다. [설치 및 클라이언트 연결 방법](MCP.md)을 참고하세요.

## 운영 참고

- 검사 기록과 종료된 장애 이력은 7일간 보관합니다. 오래된 기록은 매시간 정리합니다.
- 장애가 확정되면 대상별 검사 간격을 최대 5분까지 늘리고, 정상 응답 후 1분으로 되돌립니다.
- 브라우저는 표시 중인 탭에서 30초마다 결과를 갱신합니다. 숨긴 탭은 갱신을 멈추고 복귀 시 바로 조회합니다.
- API는 `GET /api/status`로 집계 결과를 제공합니다. 외부에서 기록을 수정하는 API는 없습니다.
- 요청 로그는 5분 단위로 종류·응답 등급·처리 시간을 집계합니다. 요청자 IP·쿼리·쿠키·인증 헤더를 이 집계에 저장하지 않습니다.
- 서비스는 루프백 주소에 바인딩하며, 배포 시 전용 계정과 systemd 파일 시스템 격리를 사용합니다.
